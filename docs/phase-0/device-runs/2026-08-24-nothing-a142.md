## YouTube harness probe

The public YouTube IFrame API example video ID `M7lc1UVf-VE` was used with an
HTTPS test origin. No account identifier or private media URL was used. That
origin did not identify the installed application ID and does not satisfy the
current Android WebView Referer requirement. This run is not identity evidence.

- A non-HTTPS origin was rejected with the expected visible validation message.
- The IFrame reached ready state and the example video was cued without a player
  error.
- The WebView container remained visible at physical bounds
  `[32,238][1053,1132]`. Standard YouTube controls, branding, attribution, and
  the Watch on YouTube surface remained visible.
- The native Play action stayed disabled until readiness handling ran.
- An automation-injected readiness tap recorded `user_ready_gesture`, followed
  by `autoplay_blocked` and a visible local recovery prompt. A trusted physical
  recovery gesture was not captured before the session ended, so successful
  playback is not claimed.
- One earlier automation tap hit the visible Watch on YouTube surface and opened
  the browser. The app was resumed and the intended native readiness control was
  then targeted. This attempt is retained as an operator error, not a provider
  failure.
- App switching produced lifecycle and top-level-navigation telemetry. Screen
  lock, advertisements, playlist transitions, coordinated play, pause, seek,
  and a second phone were not tested.
